# KnowPilot 投资机会发现与假设验证系统 — 设计规格

日期：2026-09-14  
状态：已获方向确认，已完成专业投资工作流复审，待实施计划
适用分支：`codex/feat-investment-opportunity-discovery`

## 1. 产品定位

KnowPilot 从“本地知识库工具”收敛为一个面向非专业用户的投资机会发现系统：

> 系统主动汇总变化、筛出值得关注的机会线索、解释证据，并帮助用户验证投资假设。

用户不需要先理解信息层级、事实抽取、信号聚类或事件研究。系统将复杂判断留在内部，前台只呈现：

- 发生了什么变化；
- 为什么这条变化值得关注；
- 可能影响哪些公司、资产、主题或宏观议题；
- 证据强度和不确定性；
- 下一步最值得验证什么。

系统不输出未经验证的“买入/卖出”指令，也不把观点、相关性或历史统计包装成因果结论。

本版在专业投资工作流复审后补充了五个关键边界：`信号` 不等于 `机会`；机会必须具备预期差、催化剂、时间窗口和证伪条件；人物影响采用可复核的事件研究；每日首页只输出有限数量的研究候选；所有推荐都通过事后结果复盘进行校准。

## 2. 产品事实与边界

### 2.1 目标用户

- 个人投资者或研究者，投资经验不稳定，不希望手工维护复杂信息源。
- 希望从 X、YouTube、公司公告、宏观数据等来源发现机会，但缺少系统化筛选方法。
- 需要知道“谁值得关注”以及“这个人的发言过去是否真的影响过股票”。

### 2.2 核心成功标准

1. 用户每天打开首页，30 秒内能知道最值得注意的 3–5 个变化。
2. 每条机会线索都能展开到原始来源、证据片段、时间和置信度。
3. 用户无需配置复杂规则，也能从推荐账号一键开始追踪。
4. 人物发言与市场反应的统计可以被理解、复核和关闭，不产生虚假的确定性。
5. YouTube 观点保留为重要入口，但不会绕过事实验证直接升级为事实。
6. 用户每天最多被打扰于 3–5 条高优先研究候选，其余内容进入可回看的情报池。
7. 每条研究候选都有明确的“为什么现在、如何证伪、多久得到答案”。

### 2.3 非目标

- 不做自动交易、组合管理、券商下单或收益承诺。
- 不以粉丝数、热度或点赞量作为账号价值的主要依据。
- 不删除现有知识库、文档、图谱、实体或 NotebookLM 数据。
- 不把所有历史页面一次性重写成新的后端服务；优先在现有 investment 模块上渐进改造。
- 不把“未定价”或“历史上涨”直接解释为可交易机会；它们只能作为研究候选的一个分项。

## 3. 核心工作流

系统按一个闭环工作：

`发现变化 → 归一与去重 → 提取事实 → 聚合早期信号 → 生成机会候选 → 关联观察对象/假设 → 评估市场反馈与预期差 → 推荐下一步动作 → 事后复盘 → 沉淀简报`

### 3.1 用户每日路径

1. 打开“情报流”首页，默认看到全部观察对象过去 24 小时的变化。
2. 先看最多 3–5 条“高优先研究候选”，再查看“正在发生”的新信号。
3. 打开一条候选的证据抽屉，查看预期差、催化剂、时间窗口、风险和证伪条件。
4. 对候选执行“加入验证、继续观察、建立研究任务、忽略、打开原文”之一。
5. 在“假设验证”中处理系统建议的支持/削弱/冲突证据，并可修改判断。
6. 在“研究简报”中回顾当日候选、人物影响事件、结果反馈和待跟进事项。

### 3.2 新用户路径

1. 系统先提供少量默认观察主题模板，但不强迫用户填写复杂字段。
2. “账号发现”根据主题、已有信息盲区和可验证性推荐 X、YouTube 与机构账号。
3. 用户点击“关注追踪”后，系统在 KnowPilot 内创建来源订阅、绑定主题并加入采集队列。
4. 账号内容经过事实提取和市场反馈观察后，才参与机会排序。

### 3.3 用户投资上下文（可选但必须可配置）

为避免推荐脱离用户实际，系统提供轻量设置，不要求输入持仓或敏感账户数据：

- 主要市场：美股、港股、A 股、其他；
- 关注周期：短期（数日–数周）、中期（数周–数月）、长期（数月以上）；
- 重点主题与行业；
- 最低流动性偏好；
- 不希望重复推荐的对象或主题；
- 可选的已有观察对象/持仓暴露标签（只存用户主动填写的摘要，不接券商账户）。

上下文只用于排序、去重和风险提示，不用于自动交易。

## 4. 信息架构与页面边界

### 4.1 主导航

**核心工作**

- 情报流：全量机会线索与最新变化，默认首页。
- 观察对象：公司/资产、行业主题、宏观议题、人物/机构。
- 假设验证：待处理证据、我的假设、已验证、已忽略。
- 研究简报：每日/每周机会复盘和历史快照。

**情报来源**

- 账号发现：推荐值得学习、关注和追踪的 X/YouTube/机构账号。
- YouTube 观点：视频总结、观点层标识、来源反推、提取待验证观点。
- 数据源：X、SEC、Fed、BLS、FRED、RSS、HKEX、CNINFO 等真实来源配置与任务状态。

**辅助入口（折叠）**

- 资料库：导入、文档、阅读、搜索、知识图谱、溯源图、实体、NotebookLM。
- 投资信息：高密度明细表格。
- 宏观日历：事件日历和宏观事实。
- 设置：工作区、模型和系统配置。

现有路由继续兼容；`/` 作为情报流入口，`/investment` 作为兼容地址；YouTube 路由继续有效。导航隐藏不等于数据删除。

### 4.2 情报流首页

默认范围是全部观察对象，不要求用户先选对象。页面包含：

- 顶部：日期、数据范围、全局搜索、添加情报。
- 摘要指标：值得注意、机会线索、假设受挑战、待验证。
- 快速筛选：全部对象、正在发生、一手信息、观点层、宏观、高影响、过去 24 小时。
- 主列表：最新情报卡片，默认一行摘要。
- 右侧栏：正在发生、今日动作、等待补充的证据。

情报卡片至少显示标题、来源类型、时间、一句变化摘要、影响方向、关联对象和一项推荐动作。点击后打开证据抽屉，展示原文链接、证据片段、来源可信度、AI 置信度、支持/反例数量和关联假设。

首页必须把“情报条目”“早期信号”“机会候选”分开显示：情报是原始变化，信号是聚合后的模式，机会候选是经过预期差、催化剂和风险筛选后值得研究的对象。每日默认只展示 3–5 条机会候选；用户可以展开完整信号池，但不会被无限滚动列表打扰。

### 4.3 机会候选

机会候选不是交易指令，而是一个可复盘的研究对象。每条候选必须回答：

- 发生了什么变化；
- 市场原本可能预期什么；
- 新信息改变了哪个假设或盈利/竞争路径；
- 关联资产/主题是谁，为什么是它；
- 可能的催化剂和时间窗口；
- 当前价格/成交量对信息反应了多少；
- 支持证据、反例、主要风险和明确证伪条件；
- 下一步验证动作以及预期多久得到答案。

候选状态：`new`、`researching`、`waiting_for_evidence`、`validated`、`invalidated`、`parked`。候选可由多个信号合并而来，但单一热点或单条发言不能直接升级为高优先候选。

### 4.4 账号发现

页面提供：

- 全部推荐、X 人物、YouTube 频道、机构与一手源、按主题筛选。
- 推荐卡片：名称、平台、账号标识、推荐等级、推荐原因、主题标签、样本量、有效更新频率和“关注追踪”按钮。
- 已关注列表：暂停/恢复、调整关联主题、查看最近内容、查看人物影响、取消关注。

推荐原因必须使用普通语言，例如“过去 30 天有 4 条信息后来被公司公告印证，平均早于媒体 2.1 小时”。样本不足时显示“样本不足”，不显示具有误导性的高分。

点击“关注追踪”只创建 KnowPilot 内部订阅和采集任务，不操作用户在 X 或 YouTube 的外部关注关系。

### 4.5 人物影响分析

人物影响页面由“账号发现/观察对象 → 人物/机构 → 影响分析”进入，亦可从情报卡片打开。

单次事件展示：

- 发言时间、原文和识别出的公司/股票/主题；
- 事件后 1 日、3 日、5 日的收益、相对基准的超额收益、成交量倍数和波动持续时间；
- 可能的同期干扰事件；
- “正向反应、反向反应、低影响、未形成机会”等易懂结论；
- 样本量与置信度。

人物档案展示历史命中率、平均领先时间、平均超额收益、影响强度、稳定性和最近样本。至少有 5 个可匹配事件才允许给出“影响较强/一般”的汇总判断；否则明确显示“样本不足”。

默认使用真实收盘级数据。盘中 30 分钟/2 小时窗口属于后续增强，不阻塞第一阶段交付。

人物影响页面还必须显示：有效样本数、排除样本数及原因、不同市场环境下的分组结果、正向/负向/无效事件分布、置信区间或不确定性提示，以及事件窗口是否重叠。没有至少 5 个独立且可匹配事件时，只显示“样本不足”，不生成影响强弱结论。

### 4.6 假设验证与研究简报

假设验证默认打开待处理队列，用户只需选择支持、削弱、冲突、无关或还不确定。系统自动附上证据和来源，但最终状态可编辑。

研究简报包含：今日重要变化、新机会线索、已验证/被证伪信号、人物影响事件、支持或挑战假设的证据、明日关注清单。每条结论都必须可回链到来源。

简报必须同时记录“当日推荐”和“后续结果”，以支持账号与信号权重的校准；不得只保留成功案例。

## 5. 推荐与机会排序模型

### 5.1 账号推荐评分

账号推荐是解释性排序，不是交易评级。内部可使用以下维度：

- 主题相关性；
- 来源质量（一手、人源、专家观点、确认性媒体）；
- 历史领先性；
- 后续验证率；
- 信息独立性；
- 噪音与重复转发比例；
- 对用户当前信息盲区的补足度；
- 人物影响分析的样本充分度。

前台只展示“高匹配、值得学习、一手源、样本不足”等标签，并给出理由。推荐结果需要保留评分分解，便于测试和复核。

### 5.2 信号与机会候选的分层

早期信号只说明“某种变化正在聚集”，不等于投资机会。只有同时满足以下最低门槛，才可生成机会候选：

- 至少一个可识别的资产/主题暴露关系；
- 至少一条带来源的事实证据；
- 一个可描述的影响路径（收入、成本、供需、政策、竞争或估值预期）；
- 一个时间窗口或催化剂；
- 至少一个可验证或证伪条件；
- 数据质量足以判断市场是否已经反应。

缺少任一项时，保留为“值得留意/等待补证据”的信号，不得展示为高优先机会。

### 5.3 机会候选排序

机会候选综合：新颖度、来源质量、独立来源数量、主题/假设相关性、验证程度、市场反应程度、账号历史影响稳定性、预期差可解释性、催化剂清晰度、下行风险和用户上下文匹配度。

前台分为：

- 值得留意：新变化或单一弱信号，尚不能形成机会判断；
- 值得验证：证据正在形成，有明确催化剂、验证动作和时间窗口；
- 高优先研究：多源一致、影响路径清楚、风险可描述，且市场反应与潜在变化之间存在可解释的预期差。

YouTube 观点默认属于观点层，只有经一手源、可靠数据或明确证据验证后，才提升验证等级。

“市场尚未明显反应”只代表未观察到价格反应，不代表存在机会。系统必须同时检查市场预期、资产暴露关系、影响传导路径、估值/盈利敏感性和同期事件；若无法检查，则标记“无法判断是否已定价”。

## 6. 人物发言与股票影响统计

### 6.1 事件定义

一条可分析事件必须包含：人物来源、发言时间、原文链接、关联标的或主题、事件窗口和可用市场数据。无法可靠映射标的的发言保留在情报流，但不参与股票影响统计。

### 6.2 统计窗口与基准

- 默认窗口：发言前基准区间、事件后 1D/3D/5D。
- 基准：对应市场指数或行业 ETF；个股也可使用主题配置的自定义基准。
- 指标：简单收益、超额收益、成交量相对过去窗口的倍数、实现波动变化、影响持续时间。
- 数据规范：使用复权价格，统一交易所时区和交易日历，记录数据源、延迟、缺失值和修订时间。
- 需要标记财报、宏观数据、停牌、重大公告、分红拆股和其他人物发言等同期事件，避免把相关性误读为因果。
- 重叠事件不得重复计入独立样本；同一人物连续发言需按事件簇处理并标记窗口重叠。
- 报告正向、负向和无效事件的分布、样本量、置信区间或不确定性，不只报告命中率。

### 6.3 反馈到系统

- 历史上经常提前且后续被验证：提高来源质量与机会排序权重。
- 影响短期明显但缺乏基本面验证：标记为情绪/交易型信号，限制权重。
- 多次没有稳定市场反应：降低噪音权重。
- 市场已经充分反应：降低“未定价”分项，但仍可保留为确认信息。
- 结果不稳定、样本过少或同期干扰过多：降低权重并显示“不可归因”，而不是强行给出人物影响结论。

所有统计必须展示样本量、数据时间、基准和不确定性。不得以“影响力”单独推导买卖动作。

### 6.4 事后复盘与校准

每条账号推荐、机会候选和人物影响事件都要记录结果：

- 用户是否采纳、忽略或认为无关；
- 后续是否出现预设催化剂；
- 1D/3D/5D 和定义好的事件终点实际发生了什么；
- 假设最终支持、削弱、冲突还是失效；
- 失败原因：噪音、错误映射、市场已定价、催化剂未发生、数据缺失或同期事件干扰。

系统按固定周期更新账号推荐、信号和来源权重；权重调整保留版本和原因，避免未来结果回写过去的评分（look-ahead bias）。

## 7. 领域模型与接口边界

优先复用现有模型，不新建平行数据体系：

- `InvestmentTheme`：采集和判断的主题边界。
- `InvestmentWatchlist`：用户关注的公司/资产/议题/人物视图。
- `InvestmentSource`：真实来源配置与采集状态。
- `InvestmentPersonSource`：人物/机构账号池和关注状态。
- `InvestmentItem`：统一来源条目，保留原始链接、来源层级和用户确认字段。
- `InvestmentFact`：带证据和置信度的结构化事实。
- `InvestmentSignal`：弱信号生命周期、信息差评分和市场反馈摘要。
- `InvestmentMarketFeedback`：标的或主题的市场观察值。
- `InvestmentClaim` / `InvestmentThesis`：用户可修改的验证队列与投资假设。

建议新增或扩展以下逻辑对象（具体表结构在实施计划中冻结）：

- `AccountRecommendation`：候选账号、推荐理由、评分分解、样本量、状态。
- `PersonImpactEvent`：单次发言与市场窗口统计的持久化记录，必须保存事件簇、窗口重叠、基准、复权规则、同期干扰和数据质量状态。
- `PersonImpactProfile`：按人物聚合的历史命中率、领先时间、稳定性和置信度。
- `OpportunityCandidate`：研究候选，包含资产/主题、预期差、影响路径、催化剂、时间窗口、证据、风险、证伪条件、状态和复盘结果。
- `UserInvestmentContext`：用户主动填写的市场、周期、主题、流动性和暴露偏好。
- `RecommendationOutcome`：账号推荐/机会候选的采纳结果与后续验证结果。

API 必须先定义 Pydantic schema，再实现 service。推荐、关注、影响统计、机会候选和复盘均以 workspace 为边界；关注操作幂等，重复点击不得创建重复订阅或任务。机会候选、影响事件和复盘记录必须有稳定 ID、来源快照和版本字段，禁止用当前实时结果覆盖历史判断。

## 8. 风险、权限与数据质量

- 不采集私信、受保护账号或超出用户授权范围的内容。
- 不保存 X 密码、Cookie 或会话凭证到前端、数据库或 Git；沿用现有采集器隔离策略。
- 真实数据源失败、限流、未配置和解析错误必须显式显示。
- AI 生成事实、信号、推荐理由和简报均需带证据与置信度；没有证据时降级为“待验证”。
- 市场数据缺失、时间戳不一致或标的映射不确定时，不计算影响结论，展示具体缺口。
- 市场数据必须声明供应商、复权方式、交易日历、时区、延迟和缺失处理；不同供应商数据不可无标记混算。
- 预期差、盈利影响和估值敏感性属于研究假设，必须标记为“待验证”，不能伪装成事实。
- 删除/取消关注默认采用可恢复的停用状态，不删除历史事件和证据。
- 任何涉及权限、外部账号授权或数据删除的操作需要明确确认。

## 9. 测试与验收门槛

### 9.1 专业机会发现验收

上线前必须用历史回放或时间冻结数据验证以下场景：

- 单条热门发言但无独立证据：只能生成信号，不能生成高优先机会；
- 多源一致但市场已充分反应：显示确认信息，降低未定价分项；
- 价格无反应但影响路径不清楚：显示“无法判断是否已定价”；
- 账号样本少于 5 个有效事件：只显示样本不足；
- 同一事件被 X、YouTube、新闻重复转载：按同一事件簇计数，不能伪造多源验证；
- 机会后来失败：在简报与账号档案中保留失败原因，不删除或回写成成功。

### 9.2 前端

- 情报流首页默认展示全量范围、快速筛选和空/错/加载状态。
- 账号推荐卡片展示理由、样本量和“关注追踪”；点击后调用幂等订阅接口。
- YouTube 观点保持观点层标签，并可提取待验证观点。
- 人物影响页展示事件窗口、基准、样本量和“样本不足”状态。
- 机会候选卡片展示预期差、催化剂、时间窗口、风险、证伪条件和下一步动作；情报、信号、机会三者视觉上可区分。
- 首页每日默认最多展示 3–5 条高优先研究候选，其余候选进入完整列表。
- 账号推荐和机会候选显示样本量、推荐理由及后续结果反馈。
- 导航隐藏辅助模块后，旧路由仍可访问。
- 运行：`cd frontend && npm run lint && npm run test && npm run build`。

### 9.3 后端

- schema 校验平台、账号标识、主题绑定和 workspace 隔离。
- 推荐排序在样本不足、低可信度和重复转发场景下符合规则。
- 关注操作重复请求保持幂等，并能创建/复用对应采集任务。
- 机会候选只有在满足最低门槛时才可创建；缺少预期差、催化剂、风险或证伪条件时降级为信号。
- 影响统计正确计算 1D/3D/5D 相对基准指标，处理复权、时区、交易日历、重叠窗口和同期事件，并在数据不足时降级。
- 事件研究不泄漏未来信息；历史评分与后续复盘版本隔离。
- 复盘结果可以更新推荐权重，但不会修改已保存的历史快照。
- 所有 AI 结果包含 evidence/confidence；失败任务有可查询状态。
- 运行：`cd backend && pytest && ruff check . && mypy app`。

### 9.4 回归与迁移

- 不删除既有数据；新增字段提供兼容默认值，迁移可回滚。
- 现有 YouTube、投资、来源、信号和溯源测试必须继续通过。
- 第一阶段只接入可稳定获取的收盘级市场数据，禁止用 mock 数据接入生产路径。

## 10. 分阶段交付

1. 领域契约先行：冻结 `OpportunityCandidate`、`PersonImpactEvent/Profile`、用户上下文、复盘结果和市场数据规范。
2. 市场数据与事件研究底座：接入真实收盘级数据、复权/日历/时区规则、同期事件标记和历史回放测试。
3. 应用壳层与导航收敛：首页切换到情报流，辅助模块折叠，兼容旧路由。
4. 情报流与证据抽屉：区分情报/信号/机会，提供 3–5 条有限输出、预期差和证伪条件。
5. 账号发现：推荐卡片、理由、候选账号、关注追踪、样本门槛和结果反馈。
6. 人物影响第一版：收盘级事件窗口、基准收益、成交量、重叠事件处理和档案统计。
7. 假设验证与研究简报重排：统一证据动作、机会复盘和失败结果记录。
8. 质量与运营：空/错/加载状态、任务可观测性、权重版本、回归测试、README 与运行手册。

每阶段通过对应测试和人工审阅后再进入下一阶段；不在一次提交中重写所有业务模块。
