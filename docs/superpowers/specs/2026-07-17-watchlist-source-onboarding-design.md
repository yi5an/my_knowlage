# 观察对象信息源引导设计

## 问题

当前「观察对象」页面只能展示和解绑来源；绑定入口只在「新增数据源」弹窗中。用户必须先离开正在定义的研究对象、创建来源、手动选择归属对象、再回到观察对象查看结果。这让「观察对象」不能承担研究入口的角色，也容易产生未绑定来源。

## 目标

将首次配置改为一个从观察对象开始的闭环：

```text
定义观察对象 → 绑定已有来源 / 选择来源模板 → 补全必要配置 → 立即抓取 → 查看该对象的首批信息
```

用户创建对象时可以同时使用已有来源和新建的推荐来源。所有来源创建、绑定和抓取均需显式可见；系统不会根据股票代码猜测 CIK、RSS 地址或 X 用户名。

## 非目标

- 不改变 `InvestmentWatchlist`、`InvestmentSource` 或来源绑定的数据模型。
- 不新增自动交易、投资建议或自动订阅。
- 不改写「数据源」页面的全局管理、错误查看与手动抓取职责。
- 不自动发现或验证公司证券代码、CIK、RSS 地址、社交账号。

## 信息架构

### 观察对象为主入口

「观察对象」是单个研究域的日常入口。其详情的「信息源」标签页提供：

1. **绑定已有信息源**：多选当前工作区来源，提交后调用既有绑定接口。
2. **新建并绑定**：打开精简来源配置界面；创建请求的 `default_watchlist_ids` 包含当前对象 ID。
3. **已绑定来源列表**：显示来源名、类型、抓取间隔、最近错误；保留现有解绑操作，并提供单项立即抓取。

「数据源」页仍用于跨对象维护来源、查看抓取错误、调整轮询和管理来源覆盖范围；不再是配置首个来源的唯一入口。

### 新建观察对象向导

现有“添加观察对象”弹窗改为两步向导：

1. **定义对象**：名称、类型、代码、交易所、重要性、关键词和备注。字段沿用现有校验。
2. **配置首批信息源**：
   - **已有来源**：从工作区来源库多选；创建完成后绑定到新对象。
   - **推荐模板**：按对象类型显示可选项。股票/公司可选择 SEC EDGAR、官方 RSS、官方 X；宏观主题可选择美联储 RSS、BLS、FRED、关键词 X。每项只有在用户勾选且填写所需参数（例如 CIK、RSS URL、X 用户名、序列 ID）后才会创建。
   - **自定义来源**：与模板并列，提供现有来源类型和必要参数的配置入口。
   - 允许跳过第二步，创建一个暂未配置来源的对象。

推荐仅减少配置成本，不代表来源真实可用或适合该对象。需要凭证的来源继续显示现有提示并在抓取失败时返回明确原因。

## 提交与状态流

点击“完成并开始抓取”后，前端按以下顺序执行：

1. 创建观察对象。
2. 为每个选中的已有来源调用绑定接口。
3. 为每个有效模板/自定义来源创建 `InvestmentSource`，并在创建请求中绑定新对象。
4. 对成功绑定或创建的来源发起既有异步抓取任务。
5. 关闭向导，自动选中新对象并切换到其「最新信息」标签；显示每个来源的“已绑定 / 已创建 / 抓取中 / 失败”结果和重试入口。

对象创建是该流程的最小成功单元：后续某一来源配置、绑定或抓取失败时，已创建的对象和其他成功来源保持不变。结果面板必须指出失败来源与可操作原因；用户可在对象详情或数据源页重试。

为避免重复任务，抓取仍复用后端现有的任务去重规则。用户选择同一个已有来源给多个对象绑定时，这不会复制来源；一次抓取产生的信息可按绑定关系归入相应对象。

## 前端边界与复用

- `InvestmentWatchlistPage.tsx`：承载两步向导、对象详情中的来源绑定/创建动作、首抓结果展示。
- `InvestmentSourcesPage.tsx`：保留全局管理功能，不再承担创建观察对象后的唯一绑定入口。
- `investmentApi.ts`：复用现有的创建观察对象、创建来源、绑定/解绑来源与抓取来源接口；不为纯交互重构新增后端 API。
- 抽取可复用的来源配置字段/校验组件，保证“新建并绑定”和数据源页使用一致的 `SourceType` 配置规则，避免出现两套来源请求格式。

主题中心、信息差系统、投资信息、投资假设和待验证观点不改变路由或数据语义；它们受益于来源正确绑定后产生的过滤与聚合结果。

## 错误处理

- 第二步禁止提交未补全必需配置的已选模板，并在字段处提示缺失项。
- 某个来源失败不得回滚已创建对象，也不得阻塞其他来源的创建或抓取。
- 抓取状态显示为异步任务状态；成功信息包含新增条数，失败信息包含后端返回的可读错误。
- 操作期间禁用重复提交，完成后清除临时配置，防止重复创建来源。

## 验收标准

1. 用户可在一次“添加观察对象”流程中绑定已有来源、创建新来源，或同时完成两者。
2. 对象详情的「信息源」标签页可绑定已有来源、创建并自动绑定新来源、解绑和立即抓取。
3. 每个来源模板均明确显示必须由用户提供的参数；未补齐时不能创建。
4. 成功完成向导后，所选来源自动进入抓取队列，界面显示可理解的逐项状态。
5. 一个来源失败不会删除已创建对象或其他成功来源，且用户可以重试。
6. 「数据源」页继续能够查看和维护所有来源。
7. 前端测试覆盖向导的两种来源选择、请求编排、字段校验及部分失败的结果展示。

## 测试策略

新增或扩展 `InvestmentWatchlistPage` 的 Vitest 测试：

- 两步向导能创建对象，并把选中的已有来源绑定到返回的对象 ID。
- 选择模板时，缺失 CIK、URL、用户名或序列 ID 会阻止提交；补齐后创建的请求带正确配置与绑定 ID。
- 完成后会为成功来源创建抓取任务，并选中新对象的“最新信息”内容。
- 来源部分失败时，成功项保留，错误项可读且可重试。
- 对象详情的信息源标签页可绑定已有来源与解除绑定。

在实现前先运行现有前端相关测试；实现后运行新增页面测试、前端 lint、测试套件和构建。
