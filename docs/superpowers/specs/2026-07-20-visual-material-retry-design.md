# 视觉资料保护与人工重试设计

**日期：** 2026-07-20
**状态：** 已确认，待规格审阅
**范围：** YouTube 视频视觉帧（抽帧 + OCR）的保留、人工重试与 YouTube REST 网络重试。

## 问题与目标

当前视觉分析会在持久化时无条件删除某视频已有的 `VideoFrameAnalysis` 记录，并替换其图片目录。一次后续分析若成功执行但没有任何有效 OCR 帧，会以空列表覆盖旧资料。部署重启还会恢复部分未完成视频任务，扩大这种重跑发生的机会。

目标是将视觉资料视为可保留资产：自动流程不得覆盖已有资料；只有用户明确发起且确实生成了新的有效视觉帧时，才替换旧资料。

## 行为规则

### 自动流程

- 视频已有至少一条 `VideoFrameAnalysis` 时，自动摘要、订阅轮询、启动恢复任务均跳过视觉抽帧与 OCR。
- 视频没有视觉资料时，自动流程仍可首次生成视觉资料。
- 自动流程的抽帧、OCR 或网络失败不会删除已有记录和图片。

### 人工重试

- 视频详情“视觉资料”标签页提供“重试生成”按钮，包括当前无资料的空状态。
- 按钮仅创建 `visual_analysis_retry` 异步任务；不重新下载字幕、不重新生成摘要或脑图。
- 页面展示 pending/running/succeeded/failed 状态，完成后刷新当前视频详情。
- 新分析产生至少一条有效视觉帧时，替换该视频原有帧记录和对应图片目录。
- 新分析结果为空或抛出异常时，保留旧帧记录与图片，并把原因写入任务错误信息与视频元数据。

## 原子替换与存储

视觉分析继续在临时目录完成抽帧和 OCR。只有结果非空时：

1. 将新帧准备在独立临时目录。
2. 在数据库事务中写入新 `VideoFrameAnalysis`，替换旧行。
3. 成功提交后才将新目录切换为正式目录；旧目录延后清理。

发生异常或结果为空时，临时目录被清理，正式目录和旧数据库行不变。这样图片文件与数据库记录始终配对，不会出现空列表覆盖有效旧资料。

## 后端接口与任务

- `POST /api/v1/youtube/videos/{video_id}/visual-analysis/retry`：创建或复用该视频活跃的视觉重试 `task_job`，返回任务状态。
- `GET /api/v1/youtube/videos/{video_id}/visual-analysis/status`：返回最近视觉重试任务状态与错误信息；可复用已有按视频任务查询模式。
- 新增 `visual_analysis_retry` handler，在已有任务 worker 中执行。
- handler 通过 `video_id` 加载视频，构造已有的视觉分析服务，只调用视觉分析路径。

## 前端

- `VisualEvidenceList` 标题区域显示“重试生成”按钮。
- 空状态也显示说明和同一按钮。
- 点击后禁用重复提交；定时查询任务状态。
- 成功显示“已更新”并重新请求摘要卡；失败显示“旧资料已保留”和可读错误。

## YouTube REST 网络重试

`RestYouTubeFetcher._get` 对可恢复错误重试最多 3 次，采用短暂指数退避：

- 可重试：TLS `UNEXPECTED_EOF_WHILE_READING`、连接重置、临时 DNS/连接错误、超时、HTTP 429、500、502、503、504。
- 不重试：HTTP 400、401、403、404，配额/鉴权错误和格式校验错误。
- 最终失败保留原始 path、状态码或异常摘要；不得记录 API Key。

## 验收与测试

- 已有视觉资料的视频走自动摘要时不会调用视觉分析，也不会删帧。
- 人工重试的空结果或异常保留旧记录与图片。
- 人工重试生成新帧后替换旧记录，视频详情接口返回新帧。
- 重复点击只产生一个活跃视觉重试任务。
- 前端覆盖按钮、处理中、成功刷新、失败保留提示。
- 模拟 TLS EOF/429 后重试成功；400/403 不重试。
- 后端 pytest、Ruff、相关 mypy；前端 test、lint、build。
