# X 网页采集器设计

## 1. 背景与目标

KnowPilot 需要在不依赖 X 开发者 API 额度的前提下，自动采集公开账号和关键词主题内容。

已完成的技术验证表明：X 网页会创建访客会话，并通过内部 GraphQL `UserTweets` 查询返回结构化推文数据。实测请求返回 HTTP 200，能够解析推文 ID、正文、发布时间和原文链接。登录后的 X Web 客户端还可用于关键词搜索。

本功能的目标是：

- 在长期在线的 Mac 上运行常驻采集器。
- 同时支持指定账号和关键词主题订阅。
- 自动发现 X 当前网页 GraphQL 查询 ID，减少前端版本变更造成的中断。
- 将结构化推文幂等导入 KnowPilot 投资信息系统。
- 在前端配置订阅、频率，并查看运行状态和错误。
- 不保存 X 账号密码，不提交任何会话凭证或密钥。

## 2. 范围

### 2.1 第一版包含

- 指定账号采集，例如特朗普、黄仁勋、马斯克。
- 关键词主题采集，例如“美联储”。
- 正文、作者、发布时间、原文链接、媒体、引用和互动数据解析。
- Mac `launchd` 常驻运行和异常重启。
- 本地待上传队列、自动重试和幂等导入。
- KnowPilot 数据源配置、运行状态和手动触发。
- 首次登录引导及登录失效提示。

### 2.2 第一版不包含

- 私信、收藏、关注列表等私人数据采集。
- 自动处理验证码或绕过 X 安全验证。
- 多 X 账号池和账号轮换。
- 绕过封禁、付费内容或访问权限。
- 对历史推文进行无限深度回溯。

## 3. 方案选择

采用“Mac 独立 Playwright 采集器 + KnowPilot 批量导入 API”。

不直接复用日常 Chrome 配置，因为 Chrome 配置目录锁、浏览器升级和人工使用会影响定时采集。不采用 Chrome 扩展作为第一版，因为扩展依赖浏览器前台生命周期，自动更新和后台执行也更复杂。

采集器使用独立的持久化浏览器目录。用户只需首次打开专用浏览器登录一次 X，之后由 `launchd` 调度。公开账号优先使用访客会话；关键词搜索使用持久化登录会话。

## 4. 系统架构

### 4.1 Mac 采集器

新增独立 Node.js/TypeScript 工具 `tools/x-collector`，包含以下模块：

- `config`：读取 KnowPilot 地址、本地目录、调度和安全配置。
- `browser-session`：管理访客会话和持久化登录浏览器。
- `query-discovery`：从 X 当前 `main.js` 动态发现 GraphQL 查询 ID 和 feature 声明。
- `account-collector`：执行 `UserByScreenName` 和 `UserTweets`。
- `keyword-collector`：执行 X 搜索时间线查询。
- `normalizer`：将不同 GraphQL 节点转换为统一推文模型。
- `spool`：保存尚未成功上传的数据批次。
- `uploader`：调用 KnowPilot 批量导入 API。
- `scheduler`：按订阅频率运行任务，并添加随机延迟。
- `health`：输出本地健康状态和最近运行摘要。

采集器必须是独立进程，不嵌入 FastAPI 主进程。这样浏览器崩溃、X 页面变化或本地网络问题不会影响 KnowPilot 后端服务。

### 4.2 KnowPilot 后端

新增数据源类型 `x_web`，并提供以下能力：

- 管理账号和关键词订阅配置。
- 向 Mac 采集器提供启用的订阅清单。
- 接收结构化推文批量导入。
- 按推文 ID 幂等创建或更新投资信息。
- 保存采集器心跳、最近成功时间和最近错误。
- 支持前端手动触发单个订阅。

长时间采集任务仍由 Mac 采集器执行。后端只记录调度状态和导入结果，避免 HTTP 请求长时间占用。

### 4.3 KnowPilot 前端

在“投资数据源”页面增加 `X 网页采集`：

- 新建账号订阅或关键词订阅。
- 配置采集频率、启用状态和单次最大条数。
- 查看采集器在线状态、登录状态、最近成功时间、最近新增数量和最近错误。
- 提供“立即采集”和“重新登录”命令入口。

前端不接触 X Cookie、Bearer、CSRF 或密码。

## 5. 数据契约

### 5.1 订阅模型

`InvestmentSource` 使用 `source_type = "x_web"`，`config` 至少包含：

```json
{
  "mode": "account",
  "username": "elonmusk",
  "poll_interval_seconds": 900,
  "max_items_per_poll": 50
}
```

关键词模式使用：

```json
{
  "mode": "keyword",
  "query": "美联储 OR Federal Reserve",
  "poll_interval_seconds": 1800,
  "max_items_per_poll": 50
}
```

后端使用 Pydantic 判别联合校验两种配置，不接受同时包含 `username` 和 `query` 的模糊配置。

### 5.2 统一推文模型

批量导入项包含：

- `tweet_id`
- `author_id`
- `author_username`
- `author_name`
- `text`
- `published_at`
- `url`
- `conversation_id`
- `lang`
- `media`
- `quoted_tweet`
- `reposted_tweet`
- `reply_to_tweet_id`
- `metrics`
- `raw_payload`

`media` 支持图片、视频和动图，保存原始媒体 URL、预览图和类型。`metrics` 保存回复、转发、点赞、引用、收藏和浏览数；字段缺失时保留 `null`，不伪造零值。

### 5.3 投资信息映射

- `external_id`：推文 ID。
- `source_type`：`x_web`。
- `source_name`：`@author_username`。
- `title`：作者加正文首行的有限长度摘要。
- `summary`：完整推文正文。
- `published_at`：X 返回的发布时间。
- `url`：规范化为 `https://x.com/{username}/status/{tweet_id}`。
- `info_layer`：`opinion`。
- `source_credibility`：`personal_opinion`。
- `action_status`：`pending_review`。
- `raw_payload`：保留原始结构和互动数据。

幂等键为 `workspace_id + source_type + tweet_id`。重复采集不创建新记录，但允许更新互动数据、媒体和原始响应。

## 6. API 设计

### 6.1 批量导入

`POST /api/v1/investment/import/x-posts`

请求包含 `workspace_id`、`source_id`、`collector_id` 和最多 200 条推文。响应包含：

- `items_seen`
- `items_created`
- `items_updated`
- `items_skipped`
- `errors`

单条异常不应使整个批次回滚。后端逐条验证并返回有界错误列表。

### 6.2 采集器状态

`POST /api/v1/investment/x-collector/heartbeat`

采集器定期上报版本、主机标识、登录状态、队列长度、最近成功时间和最近错误。主机标识使用本地生成的随机 ID，不上传设备序列号。

### 6.3 订阅与命令

现有数据源 CRUD 管理 `x_web` 配置。后端增加有过期时间的采集命令，Mac 采集器轮询并确认执行结果。第一版不要求从公网主动连接 Mac，也不开放 Mac 入站端口。

## 7. 采集流程

### 7.1 账号采集

1. 从后端读取启用的账号订阅。
2. 打开 X 账号页，捕获网页创建的访客会话。
3. 从 X 当前 `main.js` 发现 `UserByScreenName` 和 `UserTweets` 查询 ID。
4. 获取用户 ID，并调用 `UserTweets`。
5. 解析时间线，过滤置顶重复、广告和游标节点。
6. 按发布时间和上次游标截取新增推文。
7. 写入本地待上传队列并批量上传。

### 7.2 关键词采集

1. 检查专用持久化浏览器登录状态。
2. 使用 X 搜索页触发或调用当前搜索时间线 GraphQL。
3. 采集“最新”结果，而不是推荐排序。
4. 解析、去重、写入本地队列并上传。
5. 登录失效或出现安全验证时停止关键词任务，并上报 `auth_required`。

## 8. 调度与重试

- 账号默认每 15 分钟采集一次。
- 关键词默认每 30 分钟采集一次。
- 每次运行增加 30 至 90 秒随机延迟。
- 用户可配置频率，但第一版最短间隔为 5 分钟。
- 网络错误使用指数退避，最多自动重试 5 次。
- X 限流时优先读取响应中的等待信息，否则使用渐进冷却。
- 查询 ID 失效时清空发现缓存，重新读取 `main.js`，然后只重试一次。
- `auth_required`、验证码、账号限制不无限重试，等待用户重新登录。
- KnowPilot 不可用时将批次保存在本地 spool，恢复后按发布时间顺序上传。
- spool 采用有界磁盘配额，超出配额时停止新采集并明确告警，不静默删除数据。

## 9. 本地运行与部署

采集器配置和状态位于用户数据目录，不位于仓库：

- 浏览器配置目录
- collector ID
- 本地 spool 数据库
- 运行日志
- KnowPilot 访问凭证

使用 macOS `launchd` 管理：

- 用户登录后自动启动。
- 异常退出后自动重启。
- 不要求管理员权限。
- 安装、卸载和状态检查脚本必须幂等。

首次初始化提供交互式命令打开专用浏览器，用户自行完成 X 登录。采集器不得记录输入内容或尝试自动填写密码、验证码。

## 10. 安全与合规边界

- 不在代码、日志、数据库或 API 中输出 X 会话凭证。
- 不读取日常 Chrome 配置、密码库或其他浏览器账户。
- 不自动处理验证码，不绕过访问限制。
- 不采集私人消息、受保护账号或非订阅范围内容。
- 所有外部 URL、发布时间和响应字段都经过长度和类型校验。
- `raw_payload` 需要大小上限，避免异常响应占满数据库。
- KnowPilot 访问凭证由环境变量或本地安全配置提供，不提交 Git。

## 11. 可观测性

每次采集记录：

- `source_id`
- 开始和结束时间
- 请求次数
- 发现、创建、更新和跳过数量
- 重试次数
- 最终状态和有界错误摘要

错误类型至少包括：

- `network_error`
- `rate_limited`
- `query_changed`
- `auth_required`
- `challenge_required`
- `parse_error`
- `upload_error`

日志不得包含请求头、Cookie、Bearer、CSRF、访客令牌或完整原始响应。

## 12. 测试策略

### 12.1 采集器

- 使用脱敏固定响应测试账号和关键词时间线解析。
- 测试普通推文、长文、图片、视频、引用、转推和回复。
- 测试查询 ID 发现和缓存失效。
- 测试限流、网络失败、登录失效和响应结构变化。
- 测试 spool 重启恢复、顺序上传和磁盘配额。

### 12.2 后端

- 测试 Pydantic 判别联合配置。
- 测试批量创建、更新、跳过和部分失败。
- 测试同一批次及跨批次幂等去重。
- 测试媒体、互动数据和原始响应大小限制。
- 测试心跳和命令状态转换。

### 12.3 前端

- 测试账号和关键词表单切换及校验。
- 测试状态、错误和登录提示展示。
- 测试立即采集命令及重复点击保护。

## 13. 验收标准

- Mac 重启或用户重新登录后采集器自动恢复。
- 成功采集特朗普、黄仁勋和马斯克，每个账号至少新增 5 条。
- 成功采集“美联储”主题至少 5 条最新结果。
- 入库记录具备正文、作者、发布时间和可打开的原文链接。
- 图片、视频、引用和转推在存在时正确保存。
- 重复运行不生成重复投资信息。
- KnowPilot 暂停后恢复时，本地队列能够补传。
- 登录失效时前端明确显示“需要重新登录”，且任务不无限重试。
- 日志、Git 变更和 API 响应中不包含任何 X 会话凭证。

## 14. 已知限制与后续工作

- X 内部接口没有稳定性承诺，需要持续维护查询发现和解析测试。
- 高频访问仍可能触发限流或安全验证，第一版不承诺完全无人值守恢复。
- 第一版只支持一套 X 登录会话。
- 后续可增加规则过滤、LLM 分类、账号分组和主题质量评分，但不纳入本次实现。
