# 事件结论溯源图对比度视觉调整

## 目标

解决当前溯源 3D 画布中层面、节点与文字都集中在深色蓝紫色域，导致层级边界弱、节点标签难读、长时间审阅疲劳的问题。保留现有真实 3D、拖拽/旋转/缩放、选中聚焦、关系语义和降级视图行为。

## 选定方向：C · 浅色分析

- 画布背景使用浅灰蓝（约 `#eef2f6`），保留轻微径向高光，不使用纯白。
- 结论、事件/事实、证据三层分别使用低饱和紫、蓝、青的半透明面和细边界；三层亮度接近但色相明确区分。
- 节点使用对应层的深色实心色，保证在浅色面和背景上均有足够对比度；冲突/过期继续使用深红/深橙。
- 层级标签使用白色半透明底、深色文字和对应色边框，避免悬浮文字直接压在面片上。
- 节点文字使用深色文字、浅色半透明底和轻阴影；选中节点用深色描边与浅色光晕表达，不依赖高亮蓝色。
- 工具栏、统计徽标、提示条和图例统一为浅色卡片体系，保留语义色作为边框或强调色。

## 约束

- 不修改 API、节点布局、相机控制和数据结构。
- 不改变关系颜色的语义映射，只提高线条在浅色背景上的可见度。
- 保持 reduced-motion、无 WebGL、小屏列表视图和 2000 节点质量档位。
- 遵循 WCAG AA 的普通文本对比度目标（正文至少 4.5:1；大字号至少 3:1）。

## 验收标准

1. 三层面在默认视角下可一眼区分，且不会压过节点内容。
2. 默认节点标签可读，标签与浅色画布的对比度达到 AA 目标。
3. 选中节点、冲突节点、过期节点和关系线仍能通过颜色 + 形状/描边区分。
4. 现有前端单测、lint、生产构建和真实浏览器 E2E 全部通过。
5. 在远端页面刷新后，浅色分析风格与本地构建一致。
